# Проектирование

Договор определяется уникальным номером в реестре. Обязательство имеет номер, уникальный внутри договора. Связь между сущностями – один ко многим. Даты вводятся в формате ГГГГ-ММ-ДД. Реестр хранится в UTF-8 JSON. Прототип рассчитан на одного пользователя.

Этапы жизненного цикла и их ветки:

| Этап | Ветка | Результат |
| --- | --- | --- |
| Требования | lifecycle/01-requirements | Описание сценариев и критериев приёмки |
| Проектирование | lifecycle/02-design | Схема данных, статусы и роли |
| Реализация | lifecycle/03-implementation | Консольный прототип |
| Проверка | lifecycle/04-testing | Автоматические проверки команды и границ сроков |
| Выпуск | lifecycle/05-release | Инструкция по запуску и проверочный пример |

Ветки сохраняют контрольные точки по этапам. Согласованная версия находится в main. В личном публичном репозитории владелец управляет настройками, участник с ролью Collaborator может записывать изменения, проверяющий читает материалы по открытой ссылке. Назначения участников и правила слияния задаются владельцем после публикации. Предлагаемый порядок работы: изменения проходят проверку до включения в main.
